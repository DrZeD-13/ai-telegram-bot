## Why

Бот будет получать входящие сообщения Telegram и обрабатывать их (в том числе через нейросеть). Без записи в хранилище нельзя отличить новое сообщение от уже взятого в работу, понять исход обработки и разобрать ошибку. Нужна доменная сущность с полями пользователя, чата, текста и статусом обработки.

## What Changes

- Добавить сущность обработанного входящего сообщения Telegram в `Domain/Entity` с Doctrine-маппингом.
- Хранить данные пользователя (имя, фамилия, nickname), id чата, id сообщения, текст, дату отправки в Telegram, статус обработки, текст ошибки, даты создания и изменения записи.
- Статус — PHP enum: не обработан, обработан успешно, обработан с ошибкой.
- Добавить миграцию таблицы. Репозиторий в `Infrastructure/Persistence` — только сохранение и чтение сущности, без сценария poll/ответа бота.
- Таблица и колонки в БД (кроме очевидных `id`, `created_at`, `updated_at`) получают SQL-комментарий с назначением.

## Capabilities

### New Capabilities

- `telegram-processed-message`: хранение входящих сообщений Telegram и статуса их обработки (поля, enum статуса, уникальность сообщения в чате, SQL-комментарии таблицы и колонок).

### Modified Capabilities

- (нет)

## Impact

- Новые классы: entity в `src/Domain/Entity`, backed enum статуса, Doctrine-репозиторий в `src/Infrastructure/Persistence/Repository`.
- Схема БД: новая таблица и Doctrine-миграция.
- Тесты: unit на entity и enum по `docs/testing.md`.
- Вне scope: use case обработки очереди, вызов нейросети, отправка ответа в Telegram, webhook, offset `getUpdates`.
